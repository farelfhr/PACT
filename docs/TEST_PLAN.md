## 6. Verdict, comparison and evidence rules

Use the PRD/AGENTS verdict vocabulary unchanged. PASS requires valid setup and all required observations; VIOLATION requires reliable contradiction of approved intent. Known environment/auth/fixture/transport/tool faults are ERROR. Functioning but insufficient observation is INCONCLUSIVE. SKIPPED/CANCELED always retain reasons and audit correlation. Neither missing credentials nor timeout/missing evidence produces PASS. COMPLETED is a job lifecycle state, not whole-suite safety. Negative guard-test success must be reported as guard behavior, not a fabricated verification run.

For DENY check protected data and state as well as allowed status; for ALLOW check correct intended functionality/data. Do not add a new 401 profile here; approved status/observation vocabulary remains ADR-0001/0002 review. Redaction must preserve enough independent observation for assertions; if required evidence becomes unavailable, record coverage limitation rather than claim no disclosure.

Compare only same approved policy hash/version and compatible fixture/schema/profile/environment/runner conditions. Intentional approved version change is policy revision; incompatible or missing baselines are NOT_COMPARABLE/review needed. Preserve both old and failed/new artifacts. A model explanation cannot rewrite an expectation, verdict, evidence hash or approval history.

Future evidence records must include exact test command, test IDs and assertions, source/commit/tool versions, contract/fixture/profile/grant lineage, actual counts/results/exit status, sanitized artifact hashes/locations, negative/error controls, cleanup outcome and reviewer identity/decision where required. Local and remote CI results are separate records; no remote pass is inferred from a local test or CI YAML. Normalize only explicitly nondeterministic presentation fields with documented rules; never strip a mismatch to force parity.
